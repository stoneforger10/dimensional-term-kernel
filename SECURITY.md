# Security and limitations

Experimental; not audited, not for safety-critical instrumentation, and not a
physical-observation oracle. Do not send funds or tokens to this contract.

Report issues privately to the repository owner before publishing exploit data.
Never include credentials, raw provider receipts, wallet exports or passwords.

## Enforced boundaries

- Native sender/deployment/nonce keys prevent overwriting another calculation.
- Full immutable source coordinates, bytes, raw hash and requested symbol order
  bind every semantic report. Complete independent refetch/reasoning is required.
- Safe GitHub-only source construction avoids caller-controlled private endpoints,
  branches, path traversal and query injection. No secret documents are supported.
- Strict UTF-8, body bounds, complete data and exact commitment checks; no lossy
  normalization or truncation. Hash matches do not themselves verify semantics.
- Exact rational normalized coefficients, dimensions and affine kinds must agree.
  No confidence tolerance can cross a READY decision. Any UNKNOWN holds all units.
- Consumers bind the full module root, not a caller-selected unit table.
- Point addition, point products, mixed dimensions and target-kind substitution
  fail deterministically, before an immutable calculation can be written.
- Byte/token/integer/exponent and per-principal storage bounds constrain work;
  they do not prevent Sybil use. No Python eval, arbitrary code or external writes.
- No funds, token approvals, asset transfers, callbacks, upgrades, owner keys or
  privilege-bearing certificates. Thus no settlement or withdrawal is claimed.

## Residual risks

Multiple models can share semantic errors or follow injected prose. Independent
evaluation and exact agreement reduce leader substitution, not common-mode error.
A compromised source revision can define incorrect units. Pinning authenticates
bytes, not the author, factual truth, freshness or recognized standards. Fictional
demo definitions are not independent institutional evidence.

One interpretation per exact source/symbol set means temporary unavailability
can hold that set permanently. There is no retry/resampling override. A different
explicit source revision is a different input, not a recovery of the old report.

Inputs to arithmetic are hypothetical numbers; no measurement uncertainty,
instrument identity, physical constraints, nonlinear conversion or empirical
calibration is verified. In particular mathematical absolute temperatures can be
negative here; this kernel does not assert physical plausibility.

No global novelty, incentive compatibility, validator independence, real-world
service verification, production security or reviewer approval is guaranteed.
